# 状態マシン仕様書

本ドキュメントは `08_core_state_transition.md` と `11_core_state_transition.md` を統合し、
実装に必要な情報を整理したものである。

---

## 1. 状態一覧

Core は以下の **5状態のみ** を持つ。状態は排他的であり、同時に複数状態を取らない。

| 状態 | 英名 | 説明 |
|------|------|------|
| 待機 | IDLE | 初期状態。処理を行っていない。次の MONITORING への準備状態 |
| 監視 | MONITORING | 入力音量を継続的に監視。音量補正は行わない |
| 介入 | INTERVENING | 事故レベルと判断され、DSPによる最小限の抑制処理を実行中 |
| 停止 | SUSPENDED | 自動処理を完全停止。自動復帰しない |
| 異常 | ERROR | 内部エラー発生。自動復帰しない |

## 2. 状態遷移表

### 2.1 許可される遷移

```
IDLE ──────────────────────────────────> MONITORING
                                              │
                                              │ (事故レベル検出)
                                              ▼
                                         INTERVENING
                                              │
                                              │ (安全状態回復)
                                              ▼
                                         MONITORING

MONITORING / INTERVENING ──────────────> SUSPENDED
                                              │
                                              │ (明示的リセット)
                                              ▼
                                            IDLE

任意状態 ─────────────────────────────────> ERROR
                                              │
                                              │ (明示的リセット)
                                              ▼
                                            IDLE
```

### 2.2 遷移マトリクス

| From \ To | IDLE | MONITORING | INTERVENING | SUSPENDED | ERROR |
|-----------|:----:|:----------:|:-----------:|:---------:|:-----:|
| IDLE | - | ✓ | ✗ | ✗ | ✓ |
| MONITORING | ✗ | - | ✓ | ✓ | ✓ |
| INTERVENING | ✗ | ✓ | - | ✓ | ✓ |
| SUSPENDED | ✓ | ✗ | ✗ | - | ✓ |
| ERROR | ✓ | ✗ | ✗ | ✗ | - |

### 2.3 禁止される遷移（仕様上存在しない）

以下の遷移は**実装してはならない**：

- IDLE → INTERVENING（監視を経由しない介入は禁止）
- INTERVENING → IDLE（停止を経由しないリセットは禁止）
- ERROR → MONITORING（リセットを経由しない復帰は禁止）
- SUSPENDED → INTERVENING（再開を経由しない介入は禁止）
- SUSPENDED → MONITORING（IDLEを経由しない再開は禁止）

---

## 3. 遷移条件

### 3.1 IDLE → MONITORING

**トリガー**: `CORE_START_MONITOR` イベント

**前提条件**:
- 入力信号が有効であること
- Core が ERROR / SUSPENDED でないこと

### 3.2 MONITORING → INTERVENING

**トリガー**: `CORE_INTERVENTION_START` イベント

**前提条件（すべて満たす）**:
- 曲内平均からの統計的逸脱
- 瞬間ピークではない（一定時間継続している）
- 人間操作が行われていない

### 3.3 INTERVENING → MONITORING

**トリガー**: `CORE_INTERVENTION_END` イベント

**条件（いずれか）**:
- 音量が安全域に戻った
- 最大介入時間を超えた

### 3.4 MONITORING / INTERVENING → SUSPENDED

**トリガー**: `CORE_STOP_MONITOR` または `CORE_SUSPEND` イベント

**条件（いずれか）**:
- 明示的な停止要求
- 人間操作検知
- 入力信号の消失
- 連続異常の発生
- Core が継続監視不能と判断

### 3.5 SUSPENDED → IDLE

**トリガー**: `CORE_RESET` イベント

**条件**:
- 明示的なリセット操作
- 内部状態の完全破棄が完了

### 3.6 任意状態 → ERROR

**トリガー**: `CORE_ERROR` イベント

**条件（いずれか）**:
- 内部整合性の破綻
- 想定外例外の発生
- 安全装置として継続不能と判断

### 3.7 ERROR → IDLE

**トリガー**: `CORE_RESET` イベント

**条件**:
- 明示的なリセット操作
- 全内部状態の破棄が完了

## 4. 各状態の責務

### 4.1 IDLE

- 内部バッファの初期化維持
- 監視開始イベントの待機
- 最小限のウォームアップ処理（オプション）

**禁止事項**:
- 音量解析
- 介入判断
- 自動的な MONITORING 遷移

### 4.2 MONITORING

- 入力音量の継続的監視
- 統計値（短期LUFS等）の更新
- 事故レベル判定の実行

**禁止事項**:
- 音量補正の実行
- 意図的な抑揚への反応

### 4.3 INTERVENING

- DSPによる最小限の抑制処理
- 介入時間の計測
- 安全域復帰の監視

**禁止事項**:
- 常時補正
- 最大介入時間を超えた継続

### 4.4 SUSPENDED

- 全処理の停止
- 停止理由の保持
- リセットイベントの待機

**禁止事項**:
- 自動復帰
- 時間経過による復帰
- 監視処理

### 4.5 ERROR

- エラー情報の保持
- ログ出力
- リセットイベントの待機

**禁止事項**:
- 自動復旧
- 監視・介入処理

---

## 5. 実装制約

### 5.1 ログ必須

すべての状態遷移は以下の情報と共にログ出力すること：

- タイムスタンプ
- 遷移元状態
- 遷移先状態
- トリガーイベント
- 遷移理由（オプション）

### 5.2 暗黙的遷移の禁止

- 状態遷移は必ずイベントを経由すること
- 直接的な状態変更は禁止

### 5.3 スレッドセーフ

- 状態の読み書きは排他制御すること
- 遷移中の割り込みを防ぐこと
