# 10_core_public_interface
## Core 公開インターフェース定義（操作不可・参照専用）

本章では LevelGuard Core が
**外部に公開してよい情報／してはいけない情報**
を明確に定義する。

目的は以下である。

- UI 実装者が迷わない
- Pro / OBS / 将来拡張が Core を侵食しない
- 「見えるが触れない」境界を固定する

---

## 1. Core Public Interface の基本原則

Core の外部公開は以下に限定される。

- 状態の可視化
- 判断結果の通知
- 安全上必要な情報提供

**操作・制御・調整は一切含まれない。**

---

## 2. Core が公開してよい情報

### 2.1 現在状態（State）

Core は以下の状態を公開してよい。

- IDLE（非介入）
- MONITORING（監視中）
- INTERVENING（安全介入中）
- SUSPENDED（停止状態）
- ERROR（異常）

理由：
- UI 表示
- ログ・デバッグ
- Pro 側判断材料

※ 状態は enum として公開される

---

### 2.2 直近の判断結果

- 事故判定が発生したか（true / false）
- 介入が行われたか
- 介入終了理由（timeout / manual / auto-stop）

理由：
- 「なぜ今動いたか」を説明するため
- ブラックボックス化防止

---

### 2.3 安全関連フラグ（参照専用）

- clipping_risk_detected
- overload_risk_detected
- abnormal_variance_detected

理由：
- 視覚的警告表示
- ログ用途

※ これらのフラグは
　 外部から ON/OFF できない

---

## 3. Core が公開してはいけない情報

### 3.1 内部数値パラメータ

- 実際の補正量（dB）
- 内部しきい値
- 統計値の生データ

理由：
- 誤解・誤操作の温床
- 音楽的判断に見える危険性

---

### 3.2 次の判断予測情報

- 「もうすぐ介入する」
- 「このままだと止まる」

理由：
- 利用者の過剰反応を誘発する
- 意図しない操作を招く

---

### 3.3 AI 判断の詳細内容

- 信頼度スコア
- 内部推論結果

理由：
- Core は AI を前提にしない
- 解釈コストが高すぎる

---

## 4. UI 表示の指針（非拘束）

Core は UI を持たないが、
表示に関して以下を推奨する。

- 状態は色＋テキストで簡潔に
- 数値ではなく段階表示
- 「安全」「注意」「介入中」程度で十分

※ UI 表現は Core の責任外

---

## 5. Pro とのインターフェース境界

Core Public Interface は
Pro に対しても同一である。

Pro は以下を行ってよい。

- Core 状態の監視
- ログ保存
- プロファイルへの記録

Pro でも以下は禁止。

- Core の判断を書き換える
- Core のパラメータを直接操作する

---

## 6. 実装者向け注意

- 「後で使うかも」は公開しない
- 一度公開したものは後方互換が発生する
- 迷ったら非公開に倒す

---

## 7. 本章の位置づけ

本章は
**Core を安全装置として完結させるための防壁**
である。

操作できないことは欠陥ではなく、
仕様である。
