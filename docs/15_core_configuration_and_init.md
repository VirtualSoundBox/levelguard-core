# 15_core_configuration_and_init
## Core 設定 / 初期化フロー定義（v1.2 確定）

本章では LevelGuard Core が
**受け取る設定の範囲**と
**初期化フロー**、
および **明示的に設定できないこと**を定義する。

目的は以下の3点である。

- 実装者が「何を設定してよいか」で迷わないこと
- Core の再現性・安全性を破らせないこと
- Pro / AI 拡張との境界を固定すること

本章は v1.2 で確定している事項のみを記載する。

---

## 1. Core が受け取る設定とは何か

### 1.1 基本方針

Core が受け取る設定は
**動作モードを切り替えるためのもの**に限定される。

- 判断ロジックそのものは設定不可
- 安全装置としての挙動は固定

設定とは
「Core の性格を変えるもの」ではない。

---

### 1.2 設定の分類

Core が受け取る設定は以下の3種のみ。

- 有効 / 無効
- 監視対象の指定
- 固定パラメータ（安全範囲内）

---

### 1.3 例：許可される設定

- Core 有効化フラグ
- 監視開始トリガー
- 入力チャンネルの割当
- 事前定義された安全プロファイルの選択

※ 数値を直接指定する設定は含まれない

---

## 2. 初期化フロー

### 2.1 初期化の責務

初期化は
**Core が安全に動作可能であることを保証する工程**
である。

- 不完全な初期化状態での動作は禁止
- 初期化失敗時は稼働しない

---

### 2.2 初期化手順（文章定義）

1. Core インスタンス生成
2. 内部状態の初期化
3. 設定内容の検証
4. DSP 接続確認
5. ログ機構初期化
6. CORE_INIT イベント発火
7. 状態を IDLE に固定

この順序は変更不可。

---

### 2.3 初期化失敗時の挙動

- 初期化途中で失敗した場合
  - CORE_ERROR を発火
  - 状態を ERROR に遷移
- 自動リトライは禁止
- 明示的な reset_core() が必要

---

## 3. 実行時に変更できる設定

### 3.1 原則

実行中に変更できる設定は **存在しない**。

- 設定変更は必ず停止状態で行う
- 監視中の設定変更は禁止

---

### 3.2 例外

以下は設定変更ではなく **制御要求**として扱う。

- start_monitor()
- stop_monitor()
- reset_core()

これらは設定変更ではない。

---

## 4. 「設定できないこと」の明文化

以下は **Core では設定不可**である。

### 4.1 判断ロジック関連

- 介入条件の書き換え
- 状態遷移ルールの変更
- フェイルセーフ条件の無効化

---

### 4.2 音楽的要素

- 曲調・盛り上がりの解釈
- 歌唱表現の補正
- 抑揚の平均化

---

### 4.3 AI / 学習関連

- 学習モデルの指定
- 推論パラメータの変更
- 外部 AI の直接接続

これらはすべて Pro / 外部レイヤーの責務とする。

---

## 5. Core 設定に関する設計思想

- 設定が少ないほど安全
- 設定できないことは欠点ではない
- Core は「触れない箱」である方が信頼できる

---

## 6. 本章の位置づけ

本章は

- 初期実装の基準
- 不正利用の抑止
- Pro 拡張の余白確保

を目的とする。

Core の設定範囲を超える要求は
すべて Pro または外部設計で扱う。
