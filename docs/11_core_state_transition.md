# 11_core_state_transition
## Core 状態遷移定義（文章仕様）

本章では LevelGuard Core の
**状態遷移を文章で完全に固定**する。

図は用いない。
実装者・レビュワーが
「この状態から何が起きうるか」を
迷わず判断できることを目的とする。

---

## 1. Core に存在する状態一覧（再掲）

Core は以下の状態のみを持つ。

- IDLE
- MONITORING
- INTERVENING
- SUSPENDED
- ERROR

この5状態以外は存在しない。

---

## 2. 初期状態

### 2.1 起動時の状態

- Core 起動直後は必ず **IDLE** から開始する
- 自動的に MONITORING に遷移することはない

理由：
- 意図しない即時介入を防ぐ
- 明示的な開始フローを強制する

---

## 3. 正常系状態遷移

### 3.1 IDLE → MONITORING

**遷移条件**

- 明示的な監視開始イベントを受け取った場合
- 入力信号が有効であること

**補足**

- この遷移は一方向
- IDLE 中は一切の判断を行わない

---

### 3.2 MONITORING → INTERVENING

**遷移条件**

- 安全基準違反を検出
- Core 内部ルールにより「介入が必要」と判断

**補足**

- 事前警告状態は存在しない
- 判断と遷移は同一タイミングで行われる

---

### 3.3 INTERVENING → MONITORING

**遷移条件**

- 安全状態が回復した
- 介入継続条件が満たされなくなった

**補足**

- 介入終了＝完全復帰ではない
- 監視は継続される

---

## 4. 停止系状態遷移

### 4.1 MONITORING → SUSPENDED

**遷移条件**

- 明示的な停止要求
- 入力信号の消失
- Core が継続監視不能と判断

---

### 4.2 INTERVENING → SUSPENDED

**遷移条件**

- 強制停止要求
- 安全処理の継続が不可能
- 外部要因による中断

---

### 4.3 SUSPENDED → IDLE

**遷移条件**

- 再初期化が完了
- 内部状態が完全にクリアされた

**補足**

- 直接 MONITORING には戻らない
- 必ず IDLE を経由する

---

## 5. 異常系状態遷移

### 5.1 任意状態 → ERROR

**遷移条件**

- 内部整合性の破綻
- 想定外例外の発生
- 安全装置として継続不能と判断

---

### 5.2 ERROR → IDLE

**遷移条件**

- 明示的なリセット操作
- 全内部状態の破棄が完了

**補足**

- 自動復帰は行わない
- ERROR から他状態への直接遷移は禁止

---

## 6. 禁止される状態遷移

以下の遷移は**仕様上存在しない**。

- IDLE → INTERVENING
- IDLE → ERROR（初期化前を除く）
- INTERVENING → IDLE
- ERROR → MONITORING
- SUSPENDED → INTERVENING

理由：
- 安全性と理解性を損なうため

---

## 7. 状態遷移に関する設計思想

- 状態は少なく、意味は重く
- 暗黙遷移を作らない
- 「便利そう」な近道を作らない

Core は
**わかりにくくなるくらいなら不便を選ぶ**

---

## 8. 本章の位置づけ

本章は
- 実装の背骨
- デバッグの地図
- 将来拡張時の防波堤

である。

この状態遷移を壊す拡張は
Core では行わない。
