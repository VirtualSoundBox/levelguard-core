# ADR-001: ベースライン上限の導入

## ステータス

採用

## コンテキスト

LevelGuard Coreは、Integrated LUFSをベースラインとして使用し、Short-term LUFSとの偏差が6dBを超えた場合に介入を発動する。

しかし、以下の問題が発見された：

1. 大音量（例: -5 LUFS）で再生中にフィルタを有効化すると、その大音量がベースラインとして確立される
2. その後も大音量が続くと、Short-term ≈ Integrated となり偏差が小さい
3. 介入条件（偏差 > 6dB）を満たさず、介入が発動しない
4. 実際のテストで、有効化から介入発動まで8分かかる事象が確認された

## 検討した選択肢

### 選択肢1: ベースラインに上限を設ける（-14 LUFS）

- **メリット**: 実装がシンプル（1行追加）
- **メリット**: -14 LUFSは放送基準（EBU R128）で使用される標準値
- **デメリット**: 常に大音量のコンテンツでは頻繁に介入が発生する可能性

### 選択肢2: ピーク検出（clip条件）を強化する

- **メリット**: クリッピングレベルの音を確実に検出できる
- **デメリット**: 入力信号がOBS内部で減衰されている問題が別途存在
- **デメリット**: 閾値調整の試行錯誤が必要

### 選択肢3: 有効化時の初期ベースラインを固定値にする

- **メリット**: 有効化直後から一貫した動作
- **デメリット**: 固定値の妥当性判断が難しい（コンテンツ依存）
- **デメリット**: 通常音量のコンテンツでも固定値が適用される

## 決定

**選択肢1を採用**: ベースラインに上限 -14 LUFS を設ける

## 理由

1. **実装のシンプルさ**: `std::min(integrated_lufs, -14.0f)` の1行追加で実現可能
2. **標準値の採用**: -14 LUFSはEBU R128（欧州放送連合）の推奨ラウドネス基準であり、広く認知されている
3. **問題の直接的な解決**: 大音量で有効化しても、ベースラインは-14 LUFSに制限され、大音量との偏差が正しく検出される
4. **副作用の限定性**: 通常の音量（-14 LUFS以下）のコンテンツには影響しない

## 結果

- ベースラインは常に -14 LUFS 以下に制限される
- 大音量（例: -5 LUFS）で有効化した場合:
  - ベースライン = -14 LUFS
  - 偏差 = -5 - (-14) = +9 dB
  - 介入条件（> 6dB）を満たし、即座に介入発動
- 通常音量（例: -20 LUFS）で有効化した場合:
  - ベースライン = -20 LUFS（変更なし）
  - 従来通りの動作
