# 08_core_state_transition
## Core 状態遷移定義（実装基準）

本章は LevelGuard Core の**状態遷移・介入条件・停止条件**を定義する。
実装者が「いつ・なぜ・どう動くか」で迷わないことを目的とする。

---

## 1. 状態一覧（再掲・確定）

Core は以下の状態のみを持つ。

1. Idle（待機）
2. Monitoring（監視）
3. Intervention（介入）
4. Stopped（停止）

※ 状態は排他的であり、同時に複数状態を取らない。

---

## 2. 各状態の定義

### 2.1 Idle（待機）

- Core が有効化されているが、処理を行っていない状態
- 初期状態
- 音量解析は最小限（ウォームアップ可）

役割：
- 次の Monitoring への安全な遷移準備

---

### 2.2 Monitoring（監視）

- 入力音量を継続的に監視
- 統計値（短期）を更新
- 事故レベル判定のみを行う

制約：
- 音量補正は行わない
- 介入の「判断」までに留める

---

### 2.3 Intervention（介入）

- 事故レベルと判断された場合のみ遷移
- DSP による最小限の抑制処理を実行
- 処理は短時間・限定的

制約：
- 常時補正は禁止
- 意図的な抑揚には反応しない

---

### 2.4 Stopped（停止）

- Core の自動処理を完全停止した状態
- 監視・介入ともに行わない

特徴：
- 自動復帰しない
- 人間操作または明示的操作が必要

---

## 3. 状態遷移ルール

### 3.1 通常遷移

Idle
→（入力検知・安定後）
→ Monitoring

Monitoring
→（事故レベル検出）
→ Intervention

Intervention
→（抑制完了・安定）
→ Monitoring

---

### 3.2 人間操作による遷移

Monitoring / Intervention
→（人間操作検知）
→ Stopped

※ 人間操作は常に最優先される

---

### 3.3 異常系遷移

Monitoring / Intervention
→（連続異常・内部エラー）
→ Stopped

---

## 4. 介入開始条件（厳格）

以下を **すべて満たした場合のみ** Intervention に遷移する。

- 曲内平均からの統計的逸脱
- 瞬間ピークではない
- 一定時間継続している
- 人間操作が行われていない

※ 単発ピークは対象外

---

## 5. 介入停止条件

Intervention は以下で終了する。

- 音量が安全域に戻った
- 最大介入時間を超えた
- 人間操作が発生した

---

## 6. 停止状態からの復帰

Stopped 状態からの復帰は以下のみ。

- 利用者による明示的再有効化
- セッション再開（再起動等）

以下は禁止：

- 自動復帰
- 時間経過による復帰

---

## 7. 実装上の注意（重要）

- 状態遷移は必ずログ可能な構造にする
- 暗黙的な状態変更を行わない
- 条件分岐より状態遷移を優先する設計とする

---

## 8. 本章の位置づけ

本定義は **Core の安全性の根幹**である。
この章に反する実装はバグではなく「思想違反」と扱う。
